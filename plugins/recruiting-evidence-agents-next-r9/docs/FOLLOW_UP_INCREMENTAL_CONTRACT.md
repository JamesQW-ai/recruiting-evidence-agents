## 目的

本契约定义补件催办与增量重建控制边界。它只处理“已记录材料事件但当前没有可唯一映射附件”的事实，不判断候选人优劣、HRD 建议或 CEO 决策。

## 状态

| 状态 | 含义 | 可自动进入 |
|---|---|---|
| `Pending Review` | 本次快照发现缺件，等待用户审阅催办草稿。 | 是 |
| `Approved` | 用户逐项确认允许催办。 | 否 |
| `Sent` | 已收到真实飞书发送回执，等待负责人在对应私聊回复。 | 否 |
| `Acknowledged` | 已如实记录负责人回复；尚未验证 Base 附件。 | 是 |
| `Verified` | 新 Base 快照中的附件已按内容优先规则映射到该候选人与材料字段。 | 是 |
| `Confirmed Missing` | 负责人在原催办消息下精确回复“确认无法提供”；仅作为缺件边界，不代表材料已收到。 | 是 |

`Verified` 只能由新附件核验产生。负责人回复“已提交”、已读或任何聊天事件都不能单独完成该状态转换。`Confirmed Missing` 只能由同一负责人的原催办消息回复触发，且正文必须精确为“确认无法提供”；手工记录、自由文本、重复历史和未关联消息都不能触发该状态。

## 回复监听

- 负责人可由用户在当前对话中提供邮箱；邮箱仅保存于本次独立控制目录的对应补件项，不写入 Base、插件配置、来源材料或五个正式交付文件。发送前必须将邮箱解析为唯一 `open_id`，零个或多个匹配均停止，不按姓名猜测。
- 发送方以 `--as user` 发出补件消息后，必须要求负责人将材料直接补充到指定 Base 字段，并在上传完成后回复；同时把真实 `message_id`、负责人的 `open_id` 和发送时间登记为 `Sent`，不能把发送意图当作发送事实。
- 监听器以同一用户身份读取该负责人的 P2P 会话，检查发送时间之后的消息。单个在途补件可识别“已上传”；同一负责人有多个在途补件时，“已上传”回复必须包含对应 `FU-...` 编号或关联原催办消息。聊天中的附件不是补件证据，监听器不下载或解析它们。
- “已上传”只会改为 `Acknowledged`，并触发 `poll-and-refresh` 创建新 Base 只读快照；内容优先映射验证指定 Base 字段中的新增附件后才转为 `Verified`。未上传、延迟可见或无法映射时，补件项保持 `Acknowledged`。精确的原消息回复“确认无法提供”改为 `Confirmed Missing`，不触发 Base 刷新。
- 不使用 bot 事件监听普通用户私聊回复。bot 不在用户 P2P 会话中时无法稳定观察该回复。

## 重建规则

- `processed_index.jsonl` 以 `record_id`、`field_id`、`ordinal`、`file_token`、`sha256` 的组合记录已见附件事件。
- `follow_up.lock` 以非阻塞本地单操作者锁保护状态变更；`follow_up_state.json` 采用原子替换，`follow_up_audit.jsonl` 追加每项状态事件。控制目录不属于快照、来源 ZIP 或正式交付物。
- `export-resolution` 只能向当前 Candidate Pack `output/` 写入临时 `follow_up_resolution.json`，且必须验证其 `captured_at` 与控制状态一致。Candidate Pack 不读取控制目录、历史 output 或用户临时指定的其他目录；成功或阻断后该临时文件必须删除。
- 同一事件再次出现在快照中，不再次催办，也不再次提出重建。
- 回复刷新仍读取当前 Base 的完整元数据，但只对与前一快照具有相同 `record_id`、`field_id`、`ordinal`、`file_token` 且通过字节校验的附件复用本地字节；新增、替换和移除项保留在新快照 manifest 的 `refresh` 记录中。
- 新事件只有在材料身份可以唯一映射且文件可读取时才会解除对应补件项；`Invalid Material`、`Unmapped` 与 `Ambiguous` 仍保留给人工处理。重复材料仅在字节与 SHA-256 完全相同时记录为追溯历史，不创建补件或清理事项，也不要求删除。内容唯一映射到其他候选人的材料保留原始字节与文件名，并归入该候选人材料目录；同样不创建补件、清理或确认事项。
- `rebuild_candidate_ids` 仅是重建范围提示。执行重建时使用新的空快照目录和新的空交付目录。成功目录保留五个正式文件和 `operation_log.jsonl`；材料问题未到达明确边界时仅保留该日志。
- 本契约不声明 `Evidence Freeze`，不发送飞书消息，不写入 Base。
